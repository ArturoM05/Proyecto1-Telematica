Arquitectura PIBL + TWS

Componentes del sistema

El sistema implementado sigue una arquitectura de tres capas: cliente, proxy inverso y servidores de aplicación. Cada capa tiene una responsabilidad bien definida dentro del modelo cliente/servidor.

Proxy Inverso (PIBL)

Recibe todas las peticiones del cliente y las distribuye entre los backends usando Round Robin.

Ver RFC 2616 →

Balanceador de Carga

Distribuye las peticiones entre los tres servidores TWS de forma equitativa, con selección atómica protegida por mutex.

Ver pthreads →

Telematics Web Server

Servidor HTTP/1.1 que sirve recursos estáticos y maneja GET, HEAD y POST con concurrencia basada en hilos.

Ver socket(2) →

Caché con TTL

El PIBL implementa un caché persistente en disco. Cada recurso solicitado se almacena como archivo .cache junto a un archivo .ts con el timestamp de creación. El TTL se configura en pibl.conf o como argumento CLI al lanzar el proceso.
